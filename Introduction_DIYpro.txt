DIY-prolog の使い方   2026/5

Dosプロンプトから "DIYpro1" で起動、 "prog.pl" を読み込みます。
入力プロンプトは"?- "です。

何を読み込んだかは、"list"で clause内の改行、TAB、スペースが省かれた状態で表示されます。
コメントも省かれます。（本当は"listing."でしょうね）

新たなプログラムを読み込むのは"load(p44.pl)"のようにします。
単に"load"とすると"prog.pl"を再度読み込みます。（これも本当は"consult")

終了は"end"としました。（本当は"halt.")

先頭にスペースを入れて入力するとC言語の"system"関数を呼び出すので、
" ls"で現ディレクトリの中身が表示されます。

"prog.pl"の中には例題を入れています。

% 8-queen では、 "aq8"で92通りの解を表示します。本prologでは、入力に際し、
文末にピリオドが無ければ勝手に付けます。ですから「ENTER」キーで即実行となります。

実行の後、"rept"で、使用したメモリ量（配列サイズに対する比率）、実行時間が表示されます。

"die(X)"で"X = socrates "と表示されます";"を入れると、"X = platon "、
さらに";"を入れると、これ以上データが無いので"no"となります。

規則と事実を入れておくと、あとは推論してくれるprologの特徴が出る例題です。
別にprologが考えているわけではなく、記号処理をしているだけですけど、
なぜか考えているように見えるときがあります。

% zegra question  は、通常5つの家で5種類の属性ですが、3つでの例がQiita
に出ていたので、そのまま例題に使いました。（大丈夫か）
この中で、"_"が多数使われています。prologでは"_"はunify情報を保持しなくてもよいのですが、
body中では保持しておかないと、この例題は成功しません。
そこで、本prologでは、head中の"_"はunify情報を保持せず、body中では保持することにしています。
（この対応が正しいのかは不明）

% integer calculation では、N1=X-1としています。（本当は N1 is X-1,でしょう）

＊このように本prologは癖があります。（作者のわがままです）

内部関数
  true         成功
  fail         失敗
  write()      標準出力
  nl           改行
  assert()     新たなclauseの追加
  =            代入
  == != > >= < <= 比較演算子

＊traceは、prolog用ではなく、処理系のデバッグ用にしています。
