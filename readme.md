DIY-prolog     2026/4

自作のprologインタプリタです。最小限の機能しかありません。数値は整数が基本です。
C言語で800行程度、prologの入門書に出てくる例題を実行できる程度です。
整数のみはDIYpro1.c、実数対応はDIYpro2.c

・alloc、mallocは不使用、固定配列のみ。メモリリーク対策です。
・制御文はforとifのみ。
・WAMは理解できなかったので無視、変数同士のunifyは片方だけ記録
（WAMでは変数同士のunifyは相互参照ですが、無限ループを防ぐ自信がなかったので）
・prolog実行時の末尾処理はgeminiに相談してみましたが、動くコードは出てこず未実装
・binary treeは不使用、prologプログラムはそのまま文字配列buf[]に格納、buf中の任意の
  ところから次の区切りとなる位置を、整数配列pxe[]に格納。bufとpxeのindexは共通。
・文字列のポインタ*cを使わず、buf[]のindexで代用、strcmpなどどうしてもポインタが
  いるときは、buf+iとして代用しています。
・bufに記録するときは、indexが配列範囲内かをチェックしてメモリ破壊を予防。

このような処理系でも何かの参考になるかもと思って公開しています。

１．prolog実行の概略（知っている人には不要）

  prologでは、goal（一つのterm）に対し、matchする頭部（head）を持つclauseを選び出します。
  本prologでは、この処理を1stepとしてmatchするごとにstepをカウントアップしていきます。

  matchするhornに本体（body）があれば、これが次のgoalとなり、次のstepに移ります。
  matchしたclauseにbodyが無ければ、元のgoalの次のtermをgoalとします。これを繰り返して、
  goalがなくなれば成功、"yes"を返し、matchするclauseがなくなれば失敗、"no"を返します。

  成功の場合、一番最初のgoalに含まれていた変数が何にunifyしたのか表示します。
  ";"を入力すると、他のclauseを探しに（他の解を求めて）処理を再開します。

  matchの規則は、変数は何にでもunify、その他は同じ文字ならOK、違えば失敗となります。

２．DIY-prologの内部処理（一部手抜きの言い訳）

・goalは、bodyの一部で、bodyはclauseの一部なので、そのclauseが呼び出されたstep数と
  goalの先頭アドレス（buf[]のindex）で、goalの情報となります。

・goalに対し、プログラムの順番にheadとmatchするclauseを選びます。
  goalとheadの文字列を比較して、変数が出現すると、unify済みの変数は、
  unifyしたものと一致するか否か、unifyしていなければ、unify情報を記録、
  それ以外は同一の文字か否かで判断します。

・goalとmatchしたheadを持つclauseは、プログラム番号で記録されます。
  選択されたclauseに含まれる変数の分だけ記録する領域を確保します。1つの変数につき
  step数とindex（unifyしたtermのbuf[]中の位置）の2つの整数が必要となります。

・step数の最小値は1としていますので、unifyしていない変数のstep数は0とします。
  unifyしたものが整数の場合、step数は-1,indexのところには整数値を記録します。
  したがって、扱える整数は元々のC言語のlong int（4byte）となります。
  matchとunifyに関する情報はすべて整数となります。
  もし、変数が実数とunifyした場合は、step数は-2、indexのところは実数配列da[]への
  indexとして、実数は、da[]に記録します。

・1step毎に必要なメモリ量は、clause中の変数の数で変わりますから固定長ではなく、
  可変長になります。そのため、大きな整数配列stv[]を用意し、1step毎にmatch情報を
  記録します。情報の先頭indexをst[]に記録しておき、step数からmatch情報を取り出せる
  ようにします。

・prologでは、matchとunifyの情報はすべて記録し、バックトラック時に必要なところまで
  matchとunifyの情報を消して、新たにmatchを再開します。バックトラック時に
  matchをさかのぼるのは、1stepごとで、matchしたclauseの次のclauseから再開します。
  
・変数のunifyは、cluaseのmatch時stepとは別のstepで行われることもあるので、
  unifyの履歴情報は別の配列に記録して、これをたどって、バックトラック時にunify情報を
  消していきます。unify情報のstepに相当するところを0にします。そのために、
  情報が記録されているstv[]中の0にすべきindexを、整数配列vap[]に格納しておきます。

・プログラムの実行は整数配列への数値代入となりますので、代入操作は一か所にして、
  そこで、indexのオーバーフローとアンダーフローを見れば良さそうです。

・prologでは、否定を表現するため、バックトラックを制限するカットオペレータ!があります。
  本prologでは、フラグを設けて、当該stepがバックトラックの対象か否かを表して、
  フラグが立っているstepはバックトラックを飛ばしていきます。
  本当なら、残すべきunify情報を選別して情報を再構築、メモリを節約するところですが、
  簡単に済ましています。同様に末尾処理もしていません。

３．内蔵関数

  prologで実現した方が手っ取り早いものは、prologプログラムで実装します。
  not,eq,ne,member,appendなどです。
  
  関数は、true,fail,write,nl,assert,traceと、比較演算==,!=,>,<,>=,>=です。

  代入演算は=としています。通常のprologでは" is "なのですが、文字列中の" is "に続く
  文字列が数式か否かの判定が難しいのと、" is "に違和感があったからです。
  実数計算では、r=10.0,S=pai*r*r.のように表現したかったからです。

  実数計算は、代入式=の中だけで、通常の論理式では整数化（小数点切り捨て）して評価します。
  実数の定数は、pai,c0(高速),h0(プランク定数),q0(電子の電荷),kB(ボルツマン定数),e0(真空の誘電率）
            u0(真空の透磁率),mole(アボガドロ数),sigma(シュテファン・ボルツマン定数),deg(pai/180)
  実数の関数は、sin,cos,tan,asin,acos,atan,atan2,exp,log,log10,abs,int,sqrt,pow,rt,neg,

４．コンパイル

  gccとclangでほぼ同等の結果です。なぜか-std=gnu90で3倍速くなります。（赤い彗星ではないんですけど）
  "gcc DIYpro1.c -O3 -std=gnu90"
  実行速度は、windows11、Ryzen 5 7535HSのノートPCで、8-queenの92通りの解が20-30ms程度です。
